## 二、运行期依赖清单

以下逐项对应 `pyproject.toml` 的 `[project.dependencies]`，说明各自在系统中的实际职责。

1. **fastapi** —— 三个进程（edge/cloud/mgmt_agent）共用的 Web 框架。`edge/runtime.py:create_app()`、`cloud/main.py:app`、`mgmt_agent/main.py:app` 均基于它；请求/响应体直接复用 Pydantic 模型。
2. **uvicorn** —— ASGI 服务器。edge 由 `edge/main.py`、cloud 由 `cloud/main.py` 的 `uvicorn.run()`、mgmt_agent 由 `mgmt_agent/main.py` 启动，端口分别配置于各模块 settings（edge 9000 / cloud 8000 / mgmt 9001）。
3. **paho-mqtt** —— 北向 MQTT 客户端。边缘 `edge/cloud/mqtt_north.py:NorthMqtt`（发布事件/遥测/健康/影子并订阅 ACK、desired、manifest、command、diagnosis）；云端 `cloud/mqtt_bridge.py:attach()`；管理代理 `mgmt_agent/main.py:_mqtt_loop()` 订阅 `manifest` 与 `command`。
4. **pymodbus** —— Modbus TCP 采集，`edge/adapters/modbus_tcp.py:ModbusTcpAdapter`，以 `RegisterMap` 做寄存器到指标（振动/温度/电流）的映射，连接失败指数退避。
5. **asyncua** —— OPC UA 采集，`edge/adapters/opcua_client.py:OpcuaAdapter`，以 `NodeMap` 区分必选/可选节点，必选缺失则本轮失败、可选缺失优雅跳过。
6. **pydantic** —— 端云共享数据契约。`shared/schemas.py` 定义 `InternalSample`、`EdgeTelemetry`、`EdgeEvent`、`EdgeHealth`、`AckPayload`、`ModelManifest`、`CloudDiagnosis` 等，被三个进程共同引用。
7. **pydantic-settings** —— 环境变量与 `.env` 加载。`edge/settings.py:Settings`（含 `gw_id`、MQTT 地址、`edge_api_port`、`hmac_salt`、LLM 参数等）、`cloud/settings.py`、`mgmt_agent` 复用边缘 settings。
8. **httpx** —— 同步 HTTP 客户端。`mgmt_agent/ota.py:download()` 以流式分块（默认 4MB）下载模型工件并增量计算 sha256；`mgmt_agent/probe.py:probe_edge()` / `comprehensive_probe()` 探测边缘 `/health`。
9. **cryptography** —— 安全基础设施。`edge/security/model_signing.py`（模型签名验证）与 `edge/security/mtls.py`（双向 TLS）依赖其原语；`edge/cloud/masking.py` 的 HMAC 走标准库 `hmac`+`hashlib`，两者互补。
10. **onnxruntime** —— T2/T4 推理引擎。`edge/stream/anomaly_onnx.py:AnomalyDetector` 通过 `InferenceSession`（`CPUExecutionProvider`）运行异常检测模型，同时支持自编码器（AE）与 Isolation Forest 两种图；T4 知识检索的 `edge/knowledge/sqlite_vec.py:OnnxEmbedder` 复用同一引擎运行 `bge-small-zh-v1.5` **ONNX int8** 嵌入模型（`last_hidden_state` → CLS pooling → L2 归一化，输出 512 维）。
11. **onnx** —— 模型图构造与校验。`ensure_ae_onnx()` 在模型缺失时现场构建一个 1-D AE 评分图（`Sub→Div→Abs→ReduceMean`）并用 `onnx.checker` 校验，保证首次启动即可运行。
12. **prometheus-client** —— 指标注册与导出。`edge/runtime.py` 注册 `edge_t1_ms`/`edge_t2_ms`/`edge_t4_ms`/`edge_events_total` 以及队列深度、模型版本、降级等级等 gauge；`cloud/main.py` 注册 `cloud_events_received_total` 等；`/metrics` 端点用 `generate_latest()` 输出标准文本格式。
13. **pyyaml** —— YAML 配置解析。`edge/config_loader.py:load_yaml()` 读取 `config/current.yaml`（规则表、采样参数、降级阈值、隐私分箱等）。
14. **python-ulid** —— 事件唯一号。`edge/agent/state_machine.py:build_event()` 用 `str(ULID())` 生成 `event_id`，既全局唯一又按时间单调，是幂等去重的键。
15. **numpy** —— 数值计算。`edge/stream/window.py:SlidingWindow.push()` 用 `np.mean/std/percentile/polyfit` 计算窗口统计量，是滑窗与 T2 特征的第一层。
16. **sqlalchemy** —— 云端持久化与数据模型。`cloud/db.py` 定义 `EdgeDevice`、`EdgeEventRow`、`Watermark`、`ModelRegistry`、`RolloutPlan`、`RolloutRecord`、`ShadowRow` 等，`RolloutOrchestrator`/`ShadowEvaluator`/`RollbackManager` 均通过 `SessionLocal` 读写。
17. **psycopg[binary]** —— PostgreSQL 驱动。生产形态下云端 `DATABASE_URL` 指向 PG；开发与仿真默认 `sqlite:///./data/cloud.db`（`cloud/settings.py`），同一套 SQLAlchemy 模型无需改动。
18. **psutil** —— 资源观测。`edge/guard.py:ResourceGuard.snapshot()` 采集进程内存、磁盘可用空间与 CPU 温度，驱动降级决策。
19. **python-multipart** —— 模型注册接口 `POST /v1/models/register` 的 `UploadFile` 表单解析，由 FastAPI 在 multipart 上传时调用。
20. **tokenizers** —— T4 嵌入分词。`edge/knowledge/sqlite_vec.py:OnnxEmbedder` 用 `Tokenizer.from_file()` 直载模型目录下的 `tokenizer.json`（fast tokenizer，自动补 `[CLS]`/`[SEP]` 并按批填充/截断），**不引入 `transformers`**；tokenizers / onnxruntime 缺失或模型资产不可用时，由 `LocalKnowledge` 捕获异常并降级为 hash-embed。

## 四、可选依赖

### 4.1 llama-cpp-python（T3 端侧 LLM）

声明为可选依赖：`[project.optional-dependencies] llm = ["llama-cpp-python>=0.3.0"]`，以 `uv sync --extra llm` 安装（pyproject 注释亦说明其可跳过）。**为何可选**：它需要 C++ 编译工具链或匹配平台的预编译 wheel，在无编译器、离线或跨平台环境中往往装不上；而端侧 LLM 在架构上是**旁路的语义增强**而非告警主链路，因此不设为强依赖。

代码层的降级设计完全对齐这一取舍（`edge/agent/llm_llamacpp.py:EdgeLLM`）：

- 模型路径为空或不存在 → `available=False`，`infer()` 直接返回 `None`，仅打 info 日志；
- `import llama_cpp` 或模型加载抛异常 → 捕获后同样置 `available=False`（不抛给上层）;
- `EdgeAgentRuntime.preliminary()` 在 `degraded or not self.llm.available` 时返回确定性兜底话术（"疑似…，建议…。端侧初判，未经验证。"），因此 **T3 缺失时 T1/T2/T4 与告警链路完全不受影响**。

端侧实际使用 Qwen2.5-0.5B-Instruct 的 GGUF 量化模型（Q4_K_M 档），`max_tokens=32`、`num_ctx=2048`、`n_threads=2`，用 `create_chat_completion` 套用 chat template 保证输出可解析。

## 五、关键实现机制

### 5.1 四级推理流水线（T1/T2/T3/T4）与告警路径/LLM 路径异步解耦

**原理**：把"判定"按代价切分——T1 纯代码阈值规则（最快）、T2 判别式 ONNX 小模型、T4 本地知识检索、T3 端侧 LLM 语义初判（最慢）。**确定性的 T1/T2 告警绝不等待 T3**：样本处理中同步跑完 T1（必要时追加 T2），一旦命中即生成事件并落队列、发 MQTT 首报；T3 初判由 `asyncio.create_task` 起独立任务，在线程池中推理后作为"旁路追加"写回同一事件并单独发布。

**代码位置**：`edge/runtime.py`（`_handle_sample`、`_emit_hit`、`_fill_diagnosis`）、`edge/stream/rules.py`、`edge/stream/anomaly_onnx.py`、`edge/agent/state_machine.py`、`edge/knowledge/`。

**关键类/函数**：`RuleEngine.evaluate()` / `RuleHit`、`AnomalyDetector.is_anomaly()`、`EdgeAgentRuntime.preliminary()`、`SlidingWindow`。T2 命中且 T1 未命中 `bearing_rms_high` 时追加 `RuleHit(rule_id="t2_ae_vibration", severity="high")`，两条路径汇流为同一种事件。

**实测 P95（2C 约束）**：T1 `0.96 ms`、T2 `3.37 ms`、T3 `917.6 ms`（`scripts/bench_latency.py`）；T4 在 **ONNX 语义检索**路线下实测 `6.64 ms`（`evidence/t4_onnx_verification_report_round2.md`；`bench_latency.py` 未传 `model_dir` 时走 hash-embed 降级，测得 `0.14 ms`，无参考意义）。T1 预算 <50ms、T3 预算 <1.2s、T4 预算 <80ms 均达标，解耦使三者互不拖累。

> **T4 本地知识的实现（ONNX 语义检索）**：`edge/knowledge/sqlite_vec.py:LocalKnowledge` 默认构建 `OnnxEmbedder` —— 加载 `bge-small-zh-v1.5` 的 **ONNX int8 模型（512 维）**，用 `tokenizers` 直载 `tokenizer.json`、`onnxruntime` 做 CLS pooling + L2 归一化；检索用 `numpy` 余弦相似度取 top-k（知识库 30 条），**未引入 sqlite-vec**。模型缺失 / 依赖缺失 / 脏数据时优雅回退 `hash-embed`（32 维字节袋），`search()` 接口与返回结构保持不变（向后兼容旧签名）。

### 5.2 多协议接入适配层

**原理**：南向协议只负责"翻译"，不承载业务。所有协议统一产出 `InternalSample(device_id, source, ts, metrics)`，上层滑窗/规则/异常检测完全协议无关；新增协议只需实现适配器协议。

**代码位置**：`edge/adapters/base.py`、`modbus_tcp.py`、`opcua_client.py`、`mqtt_sparkplug.py`、`coap_sensor.py`。

**关键类/函数**：适配器统一入口 `Adapter.run(out: asyncio.Queue[InternalSample], stop: asyncio.Event)`；`ModbusTcpAdapter`（`RegisterMap`）、`OpcuaAdapter`（`NodeMap`）、`MqttSparkplugAdapter`（`spBv1.0/{group}/DDATA/{edge_node}/{device_id}`）、`CoapAdapter`（`poll_interval_s` 60–600s、`observe_mode`）。`EdgeRuntime.start()` 为每个适配器各起一个异步任务写入同一 `asyncio.Queue(maxsize=1000)`；任一路断开不影响其他路，失败仅记录并退避重连。

### 5.3 滑动窗口统计

**原理**：每个指标维护定长 `deque(maxlen=size)`，每次 `push` 当场算出统计量，原始高频波形在本地即压缩为聚合特征，是"数据最小化"的第一道闸门（上行带宽可降约 99%）。

**代码位置**：`edge/stream/window.py`。

**关键类/函数**：`SlidingWindow.push(metric, value) -> WindowStats`，输出 `avg/max/min/p95/std/slope/sample_count/zscore/last`；`p95` 用 `np.percentile(arr,95)`，`slope` 用一阶拟合 `np.polyfit(x,arr,1)[0]`（样本 <3 返回 0），`std` 用 `ddof=0`；附带 `alpha=0.2` 的 EWMA。`snapshot_id(metric)` 生成形如 `win:vibration_rms:<ts>` 的证据引用 ID。冷启动保护：窗口未满时 `slope=0`、`std=0`，避免早期抖动误报。

### 5.4 断网自治与本地 SQLite 队列

**原理**：断网时边缘完全自治，事件写入本地 SQLite（本地权威），不因网络中断丢数据；审计表通过触发器实现"只增不改删"。

**代码位置**：`edge/queue/sqlite_queue.py`、`edge/runtime.py:_replay_loop`。

**关键类/函数**：`SqliteQueue`（WAL 模式）——`append_event()`（先做 `event_id` 幂等检查，重复则抛 `EdgeError(E_CONFLICT)`，插入后回填单调递增 `seq`）、`pending_batch()`/`unacked_batch()`、`set_acked()`、`gap_detection()`、`queue_depth()`、`queue_stats()`、`audit()`/`query_audit()`；DDL 中 `audit_no_update`/`audit_no_delete` 触发器保证审计追加式（`RAISE(ABORT,'audit is append-only')`）。

### 5.5 水位线补传与幂等去重

**原理**：云端以 `last_acked_seq`（水位线）确认进度，边缘从水位线之后顺序批量补传；云端按 `event_id` 幂等去重，按 `(gw_id, seq)` 检测缺口（记录但不阻塞后续）。

**代码位置**：边缘 `edge/queue/watermark.py`、`edge/queue/sqlite_queue.py`、`edge/runtime.py:_on_ack/_replay_loop`；云端 `cloud/mqtt_bridge.py:_ingest_event()`。

**关键类/函数**：`next_batch(queue, limit=100, skip_acked=False)`、`apply_ack(queue, seq)`（**仅在前进时更新，永不回退**）、`detect_gaps()`、`replay_status() -> ReplayStatus`。云端 `_ingest_event()`：按 `event_id` 判定已存在则跳过，否则写 `edge_events`；`expected = last_acked_seq + 1`，若 `seq > expected` 则把 `{"from","to"}` 追加到 `Watermark.gaps` 并把水位线跳到当前 `seq`，随后回 `AckPayload`。边缘 `_on_ack` 收到 ACK 后调 `apply_ack`。补传循环 `_replay_loop()` 每 2 秒一批、每批 ≤100 条。

### 5.6 HMAC 脱敏

**原理**：设备标识等敏感字段**在边缘就地脱敏**（原始数据物理上不出厂）：标识用带盐 HMAC-SHA256 变成不可逆摘要，禁传字段直接剥离，连续工艺参数区间化。

**代码位置**：`edge/cloud/masking.py`。

**关键类/函数**：`hash_device_id(device_id, salt)`（`hmac.new(...).hexdigest()`）、`strip_site_fields()`（剥离 `site/customer/plant/device_id`）、`mask_process_params(value, ranges)` 与 `bin_value(value, bins)`（区间标签 `[a,b)`）、`mask_payload(payload, salt, fields_to_hash, fields_to_strip)`（返回新 dict，不改原对象）、`SaltRotator`（`rotate()/get_salt()/verify()/is_rotation_due()`，历史 salt 保留以校验旧数据，`verify` 用 `hmac.compare_digest` 恒定时间比较）。

### 5.7 设备影子（desired/reported）

**原理**：`desired` 只有云端能写、`reported` 只有边缘能写，`delta` 为差集。边缘**永不自行决定版本**，只在观测到 `desired ≠ reported` 时主动拉取并逐字段收敛。

**代码位置**：`edge/cloud/shadow.py`、`edge/runtime.py:_on_desired`；云端 `cloud/main.py:rollout()`/`register()` 与 `ShadowRow`。

**关键类/函数**：`ShadowBox` —— `set_desired()`/`apply_desired()`、`set_reported()`/`update_reported(key,value)`、`needs_pull()`（返回当前 delta）、`snapshot()`、`sync_status()`（`in_sync`/`pending_fields`/`offline_duration_s`）、`mark_offline()/mark_online()`、`incr_backlog()`。云端注册时创建影子并把 `desired` 以 retain+QoS1 发到 `edge/{gw_id}/shadow/desired`。

### 5.8 模型工厂（蒸馏→剪枝→量化→注册）

**原理**：七阶段流水线把"现场数据"迭代为"可下发模型"：数据回流 → 清洗标注 → 蒸馏 → 剪枝 → 量化 → 校准评测 → 注册。用 `threading` 管理后台任务，**不依赖 Celery**；每阶段留基线产物，产物路径记录在 `FactoryJob.artifacts`。

**代码位置**：`cloud/model_factory.py`；接口 `POST /v1/model-factory/jobs`、`GET /v1/model-factory/jobs/{job_id}`（`cloud/main.py`）。

**关键类/函数**：`ModelFactory`（`create_job`/`run_stage`/`run_all`/`submit_job`/`get_job_status`）、`PipelineStage`（七阶段枚举）、`JobStatus`、`FactoryJob`（`artifacts`/`metrics`/`context`/`config`）。约束：蒸馏温度需显式配置或取经调优默认值（非正数拒绝），评测必须含端侧回放集，校准集须含工业语料。

### 5.9 灰度发布（环形）

**原理**：不发全量，而按"五步节奏"逐环放量：内部实验（1 台）→ Canary（≈1%）→ 按站点/型号分环扩圈（10%→50%）→ 稳定窗口（默认 24h）→ 全量并保留回滚窗口（默认 7 天）。关键约束：灰度验证的不是数量比例，而是**恢复能力**。

**代码位置**：`cloud/rollout.py`；接口 `POST /v1/rollout/canary`、`POST /v1/rollout/expand`、`GET /v1/rollout/progress/{plan_id}`。

**关键类/函数**：`RolloutOrchestrator`（`create_plan`/`select_devices`/`advance_step`/`transition_state`/`can_deploy_to_canary`/`expand_ring`/`check_stable_window`/`full_release`/`get_rollout_progress`）、枚举 `RolloutStep`（五步）、`RolloutState`（发布状态机）、`RingConfig`，以及合法转换表 `_VALID_TRANSITIONS`（非法跳转抛 `ValueError`）。

### 5.10 影子验证

**原理**：新模型在 Canary 组与在线模型**并行推理，结果只记录不生效**，用现场数据比对两版 KPI，达标才切流，零业务风险。

**代码位置**：`cloud/shadow_eval.py`；接口 `GET /v1/shadow-eval/{gw_id}`。

**关键类/函数**：`ShadowEvaluator`（`record_inference`/`compute_kpi`/`compare`/`should_promote`/`confidence_interval`）、`ShadowInferenceRow`（`shadow_inference` 表）、`KpiMetric`/`KpiThreshold`/`ShadowResult`。五指标阈值：一致率 ≥ 现网 −2pp、P95 延迟 ≤ 现网 ×1.2、峰值内存 ≤ 现网 ×1.15、JSON 可解析率 ≥95%、误报率不劣化，且样本量 ≥ `min_samples`（默认 100）；结论用 Wilson 置信区间（`statistics.NormalDist`）标注。无样本时返回全 0 且 `passed=False`（宁可不放行）。

### 5.11 OTA 应用 / 回滚（A/B 槽位）

**原理**：模型/固件以 A/B 双槽部署，`current` 指向生效槽，旧槽保留供回滚；发布走"下载→校验→暂存→激活→探测→观察→成功/回滚→冻结"状态机，探针失败自动回滚并冻结问题版本。

**代码位置**：`mgmt_agent/ota.py`、`mgmt_agent/version.py`、`mgmt_agent/probe.py`；接口 `POST /ota/apply`、`POST /ota/rollback`。

**关键类/函数**：`OtaEngine`（`apply()`）、`OtaState`（11 态枚举）、模块级 `download()`（流式分块 + 增量 sha256）、`switch_slot()`、`rollback()`、`deploy()`（完整流程）、`VersionSlots`（`slot_dir`/`activate`/`rollback`/`current_version`，Windows 用 `current.txt`、兼容符号链接）、`comprehensive_probe()`。异常：`E_REQUIRES_FIRMWARE`（固件不匹配）、`E_MODEL_HASH_MISMATCH`（sha256 不符）、`E_DISK_FULL`（磁盘预检不足）。

### 5.12 资源降级矩阵

**原理**：资源紧张或长时间断网时按矩阵逐级降能力，**优先保住 T1 告警链路**；升级立即触发，恢复采用迟滞（hysteresis），需低于阈值 ×(1−margin) 才回升，避免抖动。

**代码位置**：`edge/guard.py`、`edge/guard_degrade.py`。

**关键类/函数**：`ResourceGuard.snapshot()`/`full_snapshot()`/`check_network()`/`check_offline_duration()` 产出 `GuardState`（`mem_used_mb`/`disk_free_mb`/`cpu_temp_c`/`llm_allowed`/`t2_full`/`accept_models`）；`DegradeLevel`（`NORMAL/LLM_SMALL/LLM_OFF/TEMP_THROTTLE/OFFLINE_DEGRADED/DISK_CRITICAL/EMERGENCY`，阈值：内存 3GB/3.6GB、温度默认 80℃（当前配置 85℃）、磁盘 500MB、离线 24h）；`DegradePolicy.evaluate()` 按多个高危同时触发升为 `EMERGENCY`；`DegradeManager.evaluate()`/`should_recover()` 实现迟滞恢复。`runtime._handle_sample()` 用 `guard.t2_full` 决定是否跑 T2、`guard.level == "llm_off"` 决定事件是否标记 `degraded`。

### 5.13 可观测性（Prometheus）

**原理**：edge/cloud 各暴露 `/metrics`，导出标准 Prometheus 文本；边缘指标在每次 scrape 时由运行时状态同步刷新，保证与真实状态一致。

**代码位置**：`edge/runtime.py`（指标注册 L53–73、`_export_runtime_metrics()` L384、`GET /metrics` L433）、`edge/monitoring/metrics.py`、`cloud/main.py`（L49–74、`GET /metrics` L112）；采集侧 `deploy/prometheus.yml` + `deploy/alerts.yml` + Grafana 看板 `deploy/grafana/dashboard.json`。

**关键指标**：边缘 `edge_t1_ms/edge_t2_ms/edge_t4_ms`、`edge_events_total`、`edge_queue_depth`、`edge_model_version`、`edge_desired_model_version`、`edge_degrade_level`、`edge_network_connected`、`edge_offline_duration_seconds`、`edge_cache_hit_rate`、`edge_cpu_temp_celsius`、`edge_disk_free_mb`、`edge_cloud_escalations_total`；云端 `cloud_events_received_total`、`cloud_models_registered_total`、`cloud_rollout_active`、`cloud_mqtt_connected`、`cloud_factory_jobs_total`、`cloud_rollback_total`。**"云端升级率下降"** 是关键业务指标——它下降说明端侧在进步。`_version_to_gauge()` 把语义版本串（如 `0.9.1→0.0901`）转为可比较数值，支撑"模型版本 ≠ 期望版本"的看板告警。

### 5.14 进程隔离的管理代理

**原理**：OTA 与模型槽位管理放在**独立进程**的管理代理（端口 9001）中，与边缘主应用进程隔离；主应用崩溃时它仍能存活并远程接管、回滚。地理范围内的裁定权仍在云端（"决策权在云、执行权在边"）。

**代码位置**：`mgmt_agent/main.py`、`mgmt_agent/ota.py`、`mgmt_agent/version.py`、`mgmt_agent/probe.py`、`deploy/mgmt-agent.service`。

**关键类/函数**：`mgmt_agent/main.py` 提供 `GET /health`（含 `isolated: true`、OTA 状态、边缘探针结果、当前槽位与冻结版本）、`POST /ota/apply`、`POST /ota/rollback`；`_mqtt_loop()` 订阅 `edge/{gw_id}/manifest`（自动应用）与 `.../command`（执行 rollback 指令）；`probe_edge()`/`comprehensive_probe()` 从"推理可用性/内存/磁盘/温度/输入链路"五维探测边缘健康——发布成功判据是**推理链路健康**而非"设备在线"。云端 `cloud/rollback.py:RollbackManager` 只做决策与状态编排，实际端侧回滚由 `OtaEngine`/`VersionSlots` 执行；信号→层级映射（`_SEVERITY_MAP`/`_LAYER_MAP`）：进程/探针失败→`firmware`（immediate），P95 超限/JSON 解析率骤降→`model`（delayed），内存超限→`config`（delayed），输入链路断开→`alert_only`（仅告警不回滚）。

## 六、工程实践

### 6.1 测试策略

- **框架与模式**：pytest + pytest-asyncio，`asyncio_mode="auto"`；测试位于 `tests/`，通过 `pythonpath=["."]` 直接以项目根为导入路径。
- **规模**：42 个测试文件、932 个测试用例；测试代码 17650 行（源码核心包 8894 行），测试比源码约 2:1。
- **分层覆盖**：单元层（`test_anomaly_onnx`、`test_masking_and_anomaly`、`test_queue_watermark_enhanced`、`test_guard*`、`test_ota*`、`test_rollout`、`test_shadow*`、`test_rollback`、`test_model_factory`）覆盖各机制边界；集成/端到端层（`test_e2e`、`test_e2e_full`、`test_e2e_real`、`test_e2e_cloud_collab`、`test_e2e_hardening`、`test_e2e_should`、`test_offline_autonomy`）验证主链路与断网自治；契约层（`test_shared_schemas`/`test_shared_topics`/`test_shared_errors`）锁定端云消息契约。
- **可选依赖的测试降级**：真实 MQTT 通路用 amqtt fixture，缺失时 `pytest.skip`；真实端侧推理单列 `test_edge_llm_real.py`，与 mock 版 `test_edge_llm.py` 分离，保证无声环境仍可全绿。
- **性能基线**：`scripts/bench_latency.py` 实测四级路径 P95，作为回归参考（结果存 `evidence/raw/bench_latency.txt`）。

### 6.2 静态检查

- **ruff check** 全仓（含 tests），**ruff format --check** 排除 `tests`/`plan`；规则集 `E/F/I/UP/B/SIM/N/W`，行宽 100，目标 py312。
- **mypy** 检查 `cloud edge mgmt_agent shared sim`，`ignore_missing_imports` + 第三方 override，编译期类型问题在 CI 前置拦截。
- **统一入口**：`Makefile` 的 `make check`（= lint + typecheck + test）与 `scripts/check.sh` 提供跨平台（Windows `.venv/Scripts/python.exe`、POSIX `.venv/bin/python`）一键校验。

### 6.3 CI

`.github/workflows/ci.yml` 在 push/PR 全分支触发单个 `check` job，步骤为：`actions/checkout` → `astral-sh/setup-uv` → `uv sync --all-groups` → `ruff check .` → `ruff format --check . --exclude tests --exclude plan` → `mypy cloud edge mgmt_agent shared sim` → `pytest -q`。依赖安装、静态检查、类型检查、测试四条门禁全部使用 uv，与本地开发环境保持一致。

### 6.4 部署与运行形态

`Dockerfile` + `docker-compose.edge.yml` 提供容器化编排（以 compose 键 `cpus: 2.0` / `mem_limit: 4g` 精确模拟边缘硬件、只读根文件系统、非 root 用户）；`deploy/` 提供 Prometheus 抓取配置、告警规则、Grafana 看板与 systemd 单元（`edge-agent.service` / `mgmt-agent.service`）；`scripts/e2e.sh` 按 cloud → edge → sim 顺序拉起并复现"采集→判定→上行→入库→诊断→OTA"主线；`sim/` 提供 Modbus/OPC UA/MQTT/CoAP 四类设备模拟器，实现零硬件联调。

> **小结**：本项目以 Python 3.12 + FastAPI 为骨架，用 **规则(T1) / 判别模型(T2) / 端侧 LLM(T3) / 本地知识(T4) 的四级分工**兼顾实时与深度，用**本地 SQLite 队列 + 水位线补传**承受断网，用**HMAC 就地脱敏 + 设备影子**守住合规与"决策权在云"，用**模型工厂 + 环形灰度 + 影子验证 + A/B 槽位 OTA + 资源降级矩阵**形成可恢复、可收敛的演进闭环；全部依赖由 uv 统一管理，质量由 ruff / mypy / pytest 与 CI 四道门禁保障。
