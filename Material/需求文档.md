# 端云协同 AI Agent 网关 · 需求文档

> 项目：**edge-ai-agent-gateway**（方案 V1.0 / Phase 0）｜技术栈：Python ≥ 3.12 + FastAPI｜依赖管理：**uv**
> 主场景：**离心泵驱动端轴承振动异常**（规则 `vibration_rms > 4.5` → 一级告警 `severity=high`）
> 规模基线：源码 **8894 行**（edge 41 文件 / cloud 10 文件 / mgmt_agent 5 文件 / shared 4 文件 / sim 4 文件）；测试 **42 文件 932 用例 17650 行**
> 端口约定：edge=**9000**、cloud=**8000**、mgmt_agent=**9001**、MQTT Broker=**1883**
> 四级延迟预算实测：**T1 0.96ms、T2 3.37ms、T3 917.6ms、T4 6.64ms（ONNX 语义检索路线）**
>
> 说明：本文档为 User Story 格式，按 Epic 分组，**仅描述已实现且经测试验证的能力**；"实现证据"均指向真实模块、接口与测试文件。

## Epic A · 现场数据接入与实时判定

### US-01 多协议设备接入
- **作为** 现场运维工程师，**我希望** 边缘网关能用 Modbus TCP、OPC UA、MQTT Sparkplug B、CoAP 接入异构设备并统一成内部样本，**以便** 不改上层逻辑即可纳管存量产线与低功耗终端。
- **验收标准**：
  - 四类协议各由独立适配器实现，统一输出 `InternalSample(device_id, source, ts, metrics)`，上层协议无关。
  - 采集协程写入同一个 `asyncio.Queue`，单路链路断开不影响其他路，`connected` 标志实时反映状态。
  - 连接失败按指数退避重连，适配器不向主循环抛异常。
  - CoAP 支持轮询与 observe 两种模式（低功耗链路属 Should，不影响其他链路）。
- **实现证据**：`edge/adapters/{base,modbus_tcp,opcua_client,mqtt_sparkplug,coap_sensor}.py`、`sim/{modbus_device,opcua_meter,mqtt_pump,coap_sensor}.py`；测试 `tests/test_adapters.py`、`tests/test_coap_enhanced.py`、`tests/test_e2e_real.py`（MQTT 端口 1883）。
- **优先级**：Must

### US-02 T1 规则引擎实时告警（P95 < 50ms）
- **作为** 现场运维工程师，**我希望** 阈值越限在毫秒级触发一级告警，**以便** 产线级联锁能在事故前响应。
- **验收标准**：
  - `RuleEngine.evaluate(metrics)` 返回 `RuleHit` 列表，主场景 `vibration_rms > 4.5` 命中 `severity=high`。
  - 确定性路径不依赖任何模型与 LLM，P95 < 50ms（实测 0.96ms）。
  - 规则可增删改并原子热更新，校验失败时保留旧规则、版本号不前进。
  - 同一设备同一规则 5 秒内去重，只发一次事件。
- **实现证据**：`edge/stream/rules.py`、`edge/stream/rule_loader.py`、`config/current.yaml`；测试 `tests/test_rule_hot_reload.py`、`tests/test_e2e.py`；基准 `scripts/bench_latency.py`。
- **优先级**：Must

### US-03 T2 ONNX 异常检测（P95 < 200ms）
- **作为** 设备算法工程师，**我希望** 用轻量 ONNX 自编码器在端侧判别异常，**以便** 在规则之外捕获早期劣化趋势。
- **验收标准**：
  - `AnomalyDetector.is_anomaly(window, metric)` 返回 `(bool, score)`，与阈值比较判定异常。
  - P95 < 200ms（实测 3.37ms）；T2 判异常且 T1 未命中时追加 `t2_ae_vibration`（`severity=high`）。
  - 模型加载失败时回退 numpy 评分器，完全不可用时返回 `(False, 0.0)`，绝不阻塞告警链路。
  - 资源护栏关闭 T2（`t2_full=False`）时安全跳过。
- **实现证据**：`edge/stream/anomaly_onnx.py`、`edge/guard.py`；测试 `tests/test_anomaly_onnx.py`、`tests/test_masking_and_anomaly.py`。
- **优先级**：Must

## Epic B · 端侧智能诊断与隐私保护

### US-04 T3 端侧 LLM 语义初判（P95 < 1.2s，标注"未经验证"）
- **作为** 现场运维工程师，**我希望** 告警同时给出可读的疑似原因与处置建议，**以便** 现场快速定位方向。
- **验收标准**：
  - `EdgeAgentRuntime.preliminary()` 输出 `preliminary_diagnosis` 与 `preliminary_confidence`，文本强制标注"**端侧初判，未经验证**"。
  - 通过 `create_chat_completion` 套用 chat template；JSON 解析带容错，`parse_rate` 可统计。
  - P95 < 1.2s（实测 917.6ms）；LLM 不可用或降级时给出确定性兜底话术。
  - 初判为**异步旁路**：告警事件先落地发布，初判后到，60 秒 TTL 缓存复用。
- **实现证据**：`edge/agent/llm_llamacpp.py`、`edge/agent/state_machine.py`、`edge/settings.py`；测试 `tests/test_edge_llm.py`、`tests/test_edge_llm_real.py`、`tests/test_agent_state_machine.py`。
- **优先级**：Must

### US-05 T4 本地知识检索诊断（故障链 + ONNX 语义检索）
- **作为** 现场运维工程师，**我希望** 断网时也能检索本地手册片段与故障链，**以便** 端侧给出有依据的初判。
- **验收标准**：
  - `LocalKnowledge.search(query, top_k=3)` 基于 ONNX 语义检索（`bge-small-zh-v1.5` int8 / 512 维 / `onnxruntime`，`numpy` 余弦）返回片段，模型缺失时优雅降级 hash-embed；`FaultChain.two_hop(rule_id)` 做两跳推理。
  - 检索 P95 < 80ms（实测 6.64ms，ONNX 路线）。
  - 知识包由云端下发、边缘只读，不在边缘编辑。
  - 检索结果作为初判的证据引用来源。
- **实现证据**：`edge/knowledge/{fault_chain,sqlite_vec}.py`（ONNX 语义检索 + hash-embed 降级）、`edge/knowledge/fault_chains.json`、`edge/knowledge/snippets.json`、`scripts/download_bge_onnx.py`、模型资产 `models/knowledge/current/`；测试 `tests/test_knowledge.py`。
- **优先级**：Must

### US-06 HMAC 脱敏后上行（原始数据不出厂）
- **作为** 平台管理员，**我希望** 设备标识与工艺参数在出厂前完成不可逆脱敏，**以便** 满足合规且原始数据一步都不出工厂。
- **验收标准**：
  - `hash_device_id()` 用 HMAC-SHA256 生成不可逆 `device_id_hash`；`strip_site_fields()` 剥离 `site/customer/plant/device_id`。
  - `mask_process_params()` 对工艺参数区间化（如温度 `[40,60)`），不泄露精确值。
  - `SaltRotator` 定期轮换 salt 并保留历史 salt，`verify()` 用 `hmac.compare_digest` 恒定时间比较。
  - 仅上行"事件 + 脱敏摘要"，不上行 10kHz 原始波形。
- **实现证据**：`edge/cloud/masking.py`；测试 `tests/test_masking_and_anomaly.py`、`tests/test_security.py`。
- **优先级**：Must

## Epic C · 断网自治与数据一致性

### US-07 断网自治（SQLite 本地队列）
- **作为** 现场运维工程师，**我希望** 断网期间事件落本地 SQLite 队列，**以便** 厂区断网时网关不变"哑巴"。
- **验收标准**：
  - `SqliteQueue.append_event()` 幂等去重 + 分配单调递增 `seq` + 写追加式审计。
  - 队列支持 `pending_batch`、`queue_depth`、`queue_stats`；重复 `event_id` 入队返回冲突错误。
  - 断电/重启后事件不丢，保留至少 7 天（方案设计目标；当前实现为 append-only 无自动清理）。
  - 断网期间 T1 告警链路始终保持可用。
- **实现证据**：`edge/queue/sqlite_queue.py`、`edge/runtime.py`（`_replay_loop`）；测试 `tests/test_offline_autonomy.py`、`tests/test_queue_watermark_enhanced.py`。
- **优先级**：Must

### US-08 水位线补传（幂等去重、缺口检测）
- **作为** 云端运维，**我希望** 网络恢复后按水位线顺序补传且不丢不重，**以便** 边缘与云端数据最终一致。
- **验收标准**：
  - `next_batch()` 按 `last_acked_seq` 顺序取批（每批 ≤100）；`apply_ack()` 单调不回退。
  - 云端 `_ingest_event()` 按 `event_id` 唯一索引幂等去重，并推进水位线。
  - `detect_gaps()` 识别缺号区间，缺口只记录不清空、不阻塞后续。
  - 补传完整率 100%、0 重复。
- **实现证据**：`edge/queue/watermark.py`、`cloud/mqtt_bridge.py`；测试 `tests/test_watermark.py`、`tests/test_e2e_hardening.py`。
- **优先级**：Must

### US-09 设备影子（desired/reported 对齐）
- **作为** 平台管理员，**我希望** 用设备影子描述期望与现状并只由云端决定版本，**以便** 版本决策集中、边缘只执行。
- **验收标准**：
  - 注册时云端创建影子并下发 `desired`（retain）；边缘回发 `reported`。
  - `ShadowBox` 计算 `delta`，`needs_pull()` 反映差集，`update_reported()` 更新上报键。
  - `desired` 只有云端能写、`reported` 只有边缘能写；断线可 `mark_offline`/`mark_online`。
- **实现证据**：`edge/cloud/shadow.py`、`cloud/main.py`（`POST /v1/devices/register`）、`cloud/db.py`（`ShadowRow`）；测试 `tests/test_shadow.py`、`tests/test_shadow_enhanced.py`。
- **优先级**：Must

## Epic D · 云端深度诊断与持续进化

### US-10 云端深度诊断（纯 Python 管线，带引用）
- **作为** 云端运维，**我希望** 云端融合多源证据产出带引用的正式诊断，**以便** 高风险结论有据可查。
- **验收标准**：
  - `depth_diagnosis(event)` 串联传感器分析 → 知识检索 → 故障链推理三步。
  - 输出 `CloudDiagnosis` 含 `conclusion`、`confidence`（上限 0.95）、`citations`。
  - `severity=high` 时 `requires_human_review=True`，涉停机动作强制人工审核。
  - 知识库/图谱缺失时优雅降级（空引用 + 降低置信度），结果回流至 `diagnosis/cloud`。
- **实现证据**：`cloud/diagnosis.py`（`_analyze_sensor`/`_retrieve_knowledge`/`_infer_fault_chain`）；测试 `tests/test_cloud_diagnosis.py`。
- **优先级**：Must

### US-11 模型工厂（蒸馏 → 剪枝 → 量化 → 注册）
- **作为** 设备算法工程师，**我希望** 云端流水线自动产出并注册端侧模型，**以便** 边缘模型可持续演进。
- **验收标准**：
  - `ModelFactory` 按 `PipelineStage` 顺序执行七阶段：数据回流 → 清洗标注 → 蒸馏 → 剪枝 → 量化 → 校准评测 → 注册。
  - `create_job`/`run_stage`/`run_all`/`submit_job`/`get_job_status` 全程可查询任务状态。
  - 产出 `ModelManifest` 含 `sha256`、`quant`、`requires_firmware`、`preproc_ver` 等发布必需字段。
- **实现证据**：`cloud/model_factory.py`、`cloud/main.py`（`POST /v1/model-factory/jobs`）；测试 `tests/test_model_factory.py`。
- **优先级**：Should

## Epic E · 安全发布与 OTA

### US-12 灰度发布（环形 1 → 10 → 50 → 100）
- **作为** 云端运维，**我希望** 新模型按环逐级放量并验证恢复能力，**以便** 风险可控地扩大发布。
- **验收标准**：
  - `RolloutOrchestrator` 按环形节奏推进：内部实验 1 台 → Canary → 10% → 50% → 稳定窗口 → 全量 100%。
  - `expand_ring()` 按站点/型号分组轮询 interleaving 选设备；`get_rollout_progress()` 可查进度。
  - 状态跳转受 `_VALID_TRANSITIONS` 约束，非法跳转或对已冻结计划扩圈抛错。
  - `can_deploy_to_canary()` 要求至少 1 台内部设备 `succeeded`。
- **实现证据**：`cloud/rollout.py`、`cloud/main.py`（`/v1/rollout*`）；测试 `tests/test_rollout.py`。
- **优先级**：Should

### US-13 影子验证
- **作为** 设备算法工程师，**我希望** 新模型与在线模型并行推理、只记录不生效，**以便** 用现场数据零风险决策是否切流。
- **验收标准**：
  - `record_inference()` 记录双版本推理，`compute_kpi()` 计算五项 KPI。
  - `should_promote()` 综合一致率、延迟、内存、可解析率、误报率、样本量六项判定。
  - `confidence_interval()` 给出 Wilson 置信区间；无样本时 `passed=False`（宁可不放行）。
- **实现证据**：`cloud/shadow_eval.py`、`cloud/main.py`（`GET /v1/shadow-eval/{gw_id}`）；测试 `tests/test_shadow_eval.py`。
- **优先级**：Should

### US-14 OTA 应用与回滚（A/B 槽位）
- **作为** 平台管理员，**我希望** 通过独立管理代理完成下载、校验、切槽、探针与自动回滚，**以便** 升级失败能安全退回。
- **验收标准**：
  - `OtaEngine.apply()` 走完 pending → downloading → verifying → staged → activating → probing → observing → succeeded 状态机。
  - 分块下载 + sha256 校验；`requires_firmware` 不匹配抛 `E_REQUIRES_FIRMWARE`，哈希不符抛 `E_MODEL_HASH_MISMATCH`。
  - A/B 双槽原子切换，探针失败自动 `rollback()` 并冻结该版本。
  - 提供 `POST /ota/apply`、`POST /ota/rollback` 接口。
- **实现证据**：`mgmt_agent/ota.py`、`mgmt_agent/version.py`、`mgmt_agent/main.py`；测试 `tests/test_ota_engine.py`、`tests/test_ota_enhanced.py`、`tests/test_ota_rollback.py`。
- **优先级**：Must

## Epic F · 资源保障与可观测性

### US-15 资源降级矩阵（normal / llm_small / llm_off）
- **作为** 现场运维工程师，**我希望** 资源紧张时按水位分级降级并保住告警链路，**以便** 边缘不因 OOM 崩溃。
- **验收标准**：
  - `DegradeLevel` 覆盖 NORMAL/LLM_SMALL/LLM_OFF/TEMP_THROTTLE/OFFLINE_DEGRADED/DISK_CRITICAL/EMERGENCY。
  - `DegradePolicy.evaluate(GuardState)` 依据内存/磁盘/温度/离线时长输出级别与动作列表。
  - `DegradeManager` 采用迟滞（升级立即、恢复需低于阈值 × (1−margin)），避免频繁抖动。
  - 任何降级**不默认沿用原指标**，关键告警链路始终优先。
- **实现证据**：`edge/guard_degrade.py`、`edge/guard.py`；测试 `tests/test_guard.py`、`tests/test_guard_enhanced.py`。
- **优先级**：Must

### US-16 健康上报与 Prometheus 可观测性
- **作为** 平台管理员，**我希望** 边缘周期上报健康状态并导出 Prometheus 指标，**以便** 集中监控网关运行态。
- **验收标准**：
  - 边缘按配置周期通过 MQTT 上报 `EdgeHealth`（QoS0 + retain），含输入链路与队列状态。
  - `EdgeMetrics.export_prometheus()` 导出队列深度、模型版本、降级等级、网络连通、离线时长、缓存命中率、P95 等指标。
  - edge `/metrics`、cloud `/metrics` 端点可用，`deploy/grafana/dashboard.json` 可直接导入看板。
- **实现证据**：`edge/monitoring/{metrics,metrics_endpoint,probes}.py`、`edge/runtime.py`、`cloud/main.py`；测试 `tests/test_monitoring.py`、`tests/test_dashboard_enhanced.py`。
- **优先级**：Must

### US-17 管理代理进程隔离
- **作为** 平台管理员，**我希望** 管理代理与主应用进程隔离并独立提供 OTA 与健康探测，**以便** 主应用崩溃时仍可远程接管。
- **验收标准**：
  - `mgmt_agent` 作为独立 FastAPI 服务运行于 9001，与 edge 主应用分属不同进程。
  - 提供 `GET /health`（含边缘探测结果与槽位状态）、`POST /ota/apply`、`POST /ota/rollback`。
  - `probe_edge()`/`comprehensive_probe()` 探测边缘健康并驱动回滚判定。
  - 错误返回带 `{"code","message"}`。
- **实现证据**：`mgmt_agent/{main,ota,probe,version}.py`；测试 `tests/test_ota_engine.py`、`tests/test_deployment.py`。
- **优先级**：Must

## 附：验收与运行约定

- 依赖统一由 **uv** 管理：`uv sync` 安装、`uv run pytest` 执行测试、`uv run python -m edge.main` 启动边缘；依赖声明位于 `pyproject.toml` 并由 `uv.lock` 锁定，不新增其他包管理清单。
- 所有指标基于**模拟环境 + 模拟数据**的初步验证，须显式声明局限，真机迁移后需重新实测。
- 永久安全边界：端侧**不做"一键执行"**，涉停机动作强制人工审核。
